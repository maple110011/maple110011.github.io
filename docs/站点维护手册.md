## 一、站点的技术底线（先读这个）

技术栈：Jekyll（academicpages 改装版）+ KaTeX 客户端公式渲染，部署在 GitHub Pages（master 分支根目录，push 后自动构建，约 1–2 分钟生效）。

### 1. permalink 必须带尾斜杠 ⚠️ 最容易踩的坑

Jekyll 对不带尾斜杠的 permalink（如 `permalink: /blog`）生成的是单文件 `blog.html`，
服务器只认无斜杠访问，`/blog/` 会真实 404（搜索引擎收录也会因此分裂成两种 URL）。

**规范：所有 `_pages/*.md` 的 permalink 一律写成 `permalink: /xxx/` 形式。** 新建页面照抄下面的模板即可避免：

```yaml
---
layout: default
permalink: /notes/my-new-note/     # ← 尾斜杠不能少（首页 permalink: / 除外）
title: "笔记标题"
tags: [数学, 测度论]
toc: true                          # 详情页开启左侧目录
author_profile: true               # 保留侧栏个人卡片
---
```

发布后自检方法：**用带尾斜杠的 URL 实际 curl / 点击一遍**，因为这是肉眼最不容易发现、却影响最大的故障模式（2026-08 前 `/blog/`、`/notes/` 等全部悄悄 404 了两个月）。

### 2. 数学公式的两条通道

kramdown（GFM 输入）对公式区域的处理不对称：

| 写法 | kramdown 行为 | 结论 |
|---|---|---|
| `$$..$$`（独立成行的块） | 识别为公式，内容不经过转义处理，反斜杠原样进 HTML | ✅ 块级公式放心写 |
| `$...$`（行内美元符） | 按普通文本做 span 转义处理：`\{` `\#` 等 Markdown 可转义字符前的反斜杠会被吃掉一层 | ⚠️ 必须套用下方"翻倍规则" |
| 源码里手写 `\( \)` | 同样被 span 处理，且括号本身也是可转义字符——整个定界符直接消失，输出成裸文本 | ❌ **禁止在源码里手写** |

> 关键区分：HTML 成品里看到的正常工作的 `\( \)` 几乎都是 kramdown 在**输出阶段**用 `$$` 块包装生成的，它们不会再被解析；而在源码里手写 `\( \)` 是另一回事。2026-08 曾据此误判其为安全通道并推送过一轮错误修复，后经线上验证推翻——这条教训不要再犯第二次。

历史事故实证：最优传输笔记一里源码写的 `$\{T:T_{\#}\mu=v\}$` 到 HTML 变成 `${T:T_{#}\mu=v}$`，KaTeX 遇到裸 `#` 直接渲染失败。

**行内公式的翻倍规则**：kramdown 的转义处理恰好消费一层反斜杠，所以对可转义字符（`{ } # $ % & _`）把反斜杠写成两个，到浏览器里正好剩一个给 KaTeX；字母类命令（`\mu` `\in` `\mathcal`…）前面的反斜杠不吃转义，写一个即可：

    错：$\{T:T_{\#}\mu=v\}$      → 线上 ${T:T_#\mu=v}$ 渲染失败
    对：$\\{T:T_{\\#}\\mu=v\\}$  → 线上 ${T:T_{\#}\mu=v}$ 正常渲染

2026-08 已按此规则修复六处行内公式（最优传输1、好集原理、等价关系与商集、bdl-position-paper）。全库批量自动化见第五节待办。

**竖线陷阱**：行内 `$..$` 里的裸竖线 `|` 会被 kramdown 当成表格单元格分隔符，把整段话拆成一个残破的单行表格（好集原理、最优传输2、bdl 译作开篇都曾中招）。数学里表示"满足条件"的竖线一律写 `\vert` 或 `\mid`；范数记号写 `\|`（反斜杠转义后的竖线在源码层面不会被误判为单元格，安全）。

**下划线斜体化（已知残留瑕疵，暂无系统性解法）**：同一行内出现两个以上 `_` 时（如一条长句中既有 `\mathcal{M}_1` 又有 `\mathcal{M}_t`），kramdown 会把它们配对渲染成斜体、吞掉下标记号。修复需改写记号或挪进 `$$` 块，遇到受影响的长行时顺手处理即可。

另有一个已知视觉妥协：kramdown 会把 `$$..$$` 输出成 `\( \)`，因此块级公式目前是以行内样式渲染的（不居中成 display 模式）。可接受；若想恢复居中，需要在 `_includes/head/custom.html` 的 auto-render 配置里再斟酌定界符方案。

### 3. Obsidian 标注块（callout）

`>[!definition] coupling` 这类语法原本会在网页上原样吐出 `[!definition]` 字样。
现在由 `_layouts/default.html` 底部的内联脚本在 KaTeX 渲染前同步转换为带中文标签的标注块：

- 类型→中文标签映射写在脚本的 `LABELS` 表里（定义/定理/命题/引理/推论/例/技巧/注记/问题/注意等）；
- **若未来用了表中没有的新类型**：同步改两处——JS 的 `LABELS` 映射，以及需要专属配色时 SCSS 中的 `.callout--<type>` 类（配色分三族：定理类蓝灰、中性灰绿、警告土黄）；
- 脚本依赖"转换先于 KaTeX DOMContentLoaded"这一顺序（内联脚本天然满足），不要把它挪进外部异步加载的 js 文件；
- 标注块标题里可以放公式（如 `[!proposition] $\Gamma_{\mu,v}$ 的良好性质`），会被正常渲染。

### 4. 其他已完成的结构性修正（不要再退回去）

- `_includes/head.html` 中的 `<base target="_blank">` 已删除——它曾强制**所有**链接（含站内导航）新开标签页；
- `_includes/masthead.html` 已去掉模板残留图标 `en.svg` 和未定义的 `{{ domain }}` 变量；
- 笔记正文中类似 `[第一同构定理]` 的 Obsidian 双链残骸是死链，搬运时要手工处理（见第三节流程）；
- 列表条目的标签统一用 `.tag` class，不要写内联 `style="..."`；
- `_config.yml` 已补 `url:` 字段——jekyll-feed 和 sitemap 生成绝对链接依赖它，别删。

## 二、设计规范（克制学术风）

### 设计令牌

所有颜色/字体收敛在 `assets/css/main.scss` 顶部的 `:root` CSS 变量里：

| 变量 | 值 | 用途 |
|---|---|---|
| `--ink` | #1d1d1b | 正文主色 |
| `--ink-soft` | #55524e | 次要文字 |
| `--ink-faint` | #8a8781 | 日期、元信息 |
| `--hairline` | #e3e1dc | 分隔线（唯一允许的线色） |
| `--paper` | #fdfdfc | 页面底色 |
| `--accent` | #2a5a7d | 链接（全文唯一强调色） |
| `--serif` / `--sans` / `--mono` | 思源宋体栈 / 黑体栈 / 等宽栈 | 正文与标题=宋体，UI 与元信息=黑体 |

深色模式 = `body.dark-mode` 里**重定义同一批变量**（中性石墨系，非蓝紫）。
给新组件写样式时只用这些变量，深色模式即自动适配，不需要再追加 `body.dark-mode .xxx` 特例。

### 组件命名约定（写新页面复用即可）

- 存档列表：`ul.note-list > li.note-list-item`，内含 `.note-title` / `.note-excerpt` / `.note-meta`；
- 标签：`.tag`（方角、描边、无填充）；笔记页筛选条：`.tag-filter`（active 态自动反白）；
- 近期动态：`.recent-updates` + `.update-date`（等宽小字日期）；
- TOC：在 frontmatter 写 `toc: true`，布局自动注入，不用手写。

### 反"AI 味"负面清单（改版时严禁回潮）

1. 彩色填充药丸标签 / 圆角卡片 + 投影 / hover 位移缩放动画；
2. emoji 当图标（🌙☀️✨🚀 一律禁止）；
3. 海军蓝、渐变、"科技感"配色；
4. 空洞口号式文案（"探索XX的研究者，喜欢深入技术细节"这类谁都能写的自我介绍）；
5. 一切内容用"待补充/敬请期待"占位框挂着——宁可诚实地只列已有的东西。

好的参照物：主页 `about.md`（第一人称、有具体事实）、日志页口吻说明（"未必严谨，但求真实"）。

## 三、Obsidian → 网站搬运 SOP（collections 版，2026-08 起）

内容已按集合组织：`_notes/`（笔记）、`_logs/`（日志）、`_translations/`（译作）；列表页与主页"近期动态"由 Liquid **自动汇总**，不再手工登记。

每篇新内容的固定流程：

1. **落一个文件**：放进对应集合目录，文件名用英文短横线 slug（决定默认 URL：notes→`/notes/<文件名>/`、logs→`/blog/<文件名>/`、translations→`/translations/<文件名>/`）。若写了显式 `permalink:` 则以它为准（历史迁移的中文文件名笔记均如此保平安）。
2. **frontmatter 模板**：

```yaml
---
title: "标题"
date: 2026-MM-DD          # 排序与主页动态按此字段
tags: [数学, 测度论]
excerpt: "一两句话的摘要，显示在列表页"
---
```

   layout / author_profile / toc 由 `_config.yml` 的 collection defaults 统一注入，不用写。
3. **正文处理**沿用第一节第 2、3 条：行内 `$..$` 套翻倍规则、禁裸竖线（用 `\vert` / `\mid`）、`>[!type]` 标注块直接用、不留 `[[wiki]]` 死链。
4. push 即完成——CI 会构建校验；两个列表页与主页动态无需任何编辑。
5. 注意两处仍然手工维护的例外：笔记页顶部的**标签筛选条**（新标签要手动加一个 `<span class="tag">`），以及成果页的项目卡片。

## 四、验证手段

### 本机无 Ruby 时

| 检查项 | 方法 |
|---|---|
| SCSS 语法 | 去掉 frontmatter 后存临时文件，`npx -y sass --load-path=_sass --load-path=. tmp.scss out.css` |
| 内部链接完整性 | python 正则收集所有 `href="/..."` 与各页 permalink/集合 URL 交叉比对（容忍带/不带尾斜杠，但两者都必须解析成功） |
| Frontmatter 合法性 | pyyaml 逐文件 `safe_load` |
| 构建结果 | 看 GitHub Actions："Jekyll CI" workflow 每次 push 自动 `bundle exec jekyll build`，绿色即通过；产物 site-dist 可下载检查 |

### Ruby 环境（CI 或本地装好后）

优先 `bundle exec jekyll build` 本地验证再 push。

### 切换 Pages 为 Actions 部署（可选升级）

仓库 Settings → Pages → Source 改为 *GitHub Actions*，然后把
`.github/workflows/pages-deploy.yml.disabled` 重命名为 `.yml`
（并按其头部注释把 jekyll-ci 的 push 触发改为仅手动，避免双流水线）。
此后部署由本文件完全接管：Ruby 版本、依赖、构建参数全部可复现，且不再受经典集成器限制。切换属于可逆操作（改回 Source 即回旧模式）。

2. **Gemfile.lock 缺 Linux 平台（CI 已绕行）**：锁文件只在 Windows 上生成过，PLATFORMS 仅 `x64-mingw-ucrt`，导致 Ubuntu 的 `bundle install` 失败（exit 16）。jekyll-ci.yml 现以 `gem install github-pages -v 227` 直装绕行；彻底修法 = 在任意 Ruby 环境执行 `bundle lock --add-platform x86_64-linux` 并提交新锁，然后把 CI 改回 setup-ruby 的 bundler-cache 用法。
3. **Cloudflare Pages 项目"maple001"构建失败**：仓库历史关联了一个 CF Pages 部署管道，近两次 push 均失败。本站 maple110011.github.io 由 GitHub Pages 正常发布、不受影响；若该 CF 项目仍在使用需到 Cloudflare 控制台看日志排查，若已废弃建议解绑。
4. **行内公式规范化脚本**：扫描 `$..$` 区域自动翻倍"单反斜杠 + 可转义字符"（跳过 `$$..$$`、代码块），根治剩余隐患；源码手写 `\( \)` 在本站不可用（见第一节第 2 条）。
5. **深色模式防闪白（FOUC）**：初始化逻辑目前在 `default.html` 页尾；把那段判断挪到 `<head>` 即可。
